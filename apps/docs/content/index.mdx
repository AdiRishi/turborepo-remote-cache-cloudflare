# A Turborepo remote cache you host yourself

Build it once, anywhere on your team, and every other laptop and CI runner replays it instead of building it again. The artifacts live in storage you own, on a server you deploy to Cloudflare Workers with one button, or build for Node.js, Vercel, AWS Lambda, and more.

[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/AdiRishi/turborepo-remote-cache-cloudflare) [Read the docs](/introduction)

## Why host your own cache

- **No Vercel account.** `turbo` talks to your server through the official Remote Cache API, and your artifacts never touch Vercel.
- **Free to start.** The Workers free plan includes 100,000 requests a day, and R2 includes 10 GB of storage a month. R2 charges nothing for egress, so the bandwidth of every cache download is free.
- **Your choice of storage.** Keep artifacts in R2, Workers KV, any S3-compatible bucket, or anything with a [Files SDK](https://files-sdk.dev) adapter.
- **A dashboard at the root.** Open the server's URL to see the time the cache saved you, its hit rate, and which teams, CI providers, and coding agents use it.
- **Signed artifacts.** The server stores each artifact's signature and returns it unchanged, so `turbo` can reject anything it didn't sign.

## Set it up

<Steps>
    <Step title="Deploy the Worker">
        The [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/AdiRishi/turborepo-remote-cache-cloudflare) button copies this repository to your GitHub or GitLab account and deploys it with an R2 bucket. You can also [deploy with Wrangler](/deploy/cloudflare).
    </Step>
    <Step title="Set a token">
        Generate a long random token and add it to the Worker as a secret named `TURBO_TOKEN`.

        ```sh
        openssl rand -hex 32
        ```
    </Step>
    <Step title="Point turbo at the Worker">
        Set these variables in your Turborepo repository, then build twice with `--cache=remote:rw` and `--cache=remote:r`. The second run ends with `FULL TURBO`, because every task came back from your Worker.

        ```sh
        export TURBO_API='https://turborepo-remote-cache.<your-subdomain>.workers.dev'
        export TURBO_TOKEN='<your token>'
        export TURBO_TEAM=my-team
        ```
    </Step>
    <Step title="Sign your artifacts (optional, recommended)">
        Turn on `remoteCache.signature` and give every machine the same `TURBO_REMOTE_CACHE_SIGNATURE_KEY`. `turbo` then rejects any artifact your own machines didn't sign, even one uploaded with a valid token.
    </Step>

</Steps>

[Get started](/get-started) has every step, [Connect turbo](/connect-turbo) brings in your team and CI, and [Sign artifacts](/sign-artifacts) locks it down.
