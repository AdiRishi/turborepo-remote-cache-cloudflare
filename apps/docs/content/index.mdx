# A Turborepo remote cache you host yourself

Deploy it to Cloudflare Workers with one button, or run the same server on AWS Lambda, Vercel, Netlify, Node.js, Bun, or Deno. Artifacts stay in R2, Workers KV, or any S3-compatible bucket, and a dashboard shows the build time your cache saves.

[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/AdiRishi/turborepo-remote-cache-cloudflare) [Read the docs](/introduction)

## Why host your own cache

- **No Vercel account.** `turbo` talks to your server through the official Remote Cache API, with no plugin, no fork, and no `turbo login`.
- **Free to start on Cloudflare.** The Workers free plan includes 100,000 requests a day, and R2 stores 10 GB a month for free. R2 charges nothing for egress, so cache downloads cost no bandwidth.
- **Your choice of storage.** Keep artifacts in R2, Workers KV, any S3-compatible bucket, or anything with a [Files SDK](https://files-sdk.dev) adapter.
- **Signed artifacts.** The server stores each artifact's signature and returns it unchanged, so `turbo` can reject any artifact that your own machines didn't sign.

## Set it up

<Steps>
    <Step title="Deploy the Worker">
        The [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/AdiRishi/turborepo-remote-cache-cloudflare) button copies this repository to your GitHub or GitLab account and deploys it with an R2 bucket. You can also [deploy with Wrangler](/deploy/cloudflare).
    </Step>
    <Step title="Set a token">
        Generate a long random token and add it to the Worker as a secret named `TURBO_TOKEN`.

        ```sh
        openssl rand -hex 32
        ```
    </Step>
    <Step title="Point turbo at the Worker">
        Add the Worker to your root `turbo.json`, and give every machine the token as `TURBO_TOKEN`.

        ```json turbo.json
        {
            "remoteCache": {
                "apiUrl": "https://turborepo-remote-cache.<your-subdomain>.workers.dev",
                "teamSlug": "my-team"
            }
        }
        ```
    </Step>
    <Step title="Sign your artifacts">
        This step is optional, and we recommend it. Turn on `remoteCache.signature` and give every machine the same `TURBO_REMOTE_CACHE_SIGNATURE_KEY`. `turbo` then rejects any artifact your own machines didn't sign, even one uploaded with a valid token.
    </Step>

</Steps>

[Get started](/get-started) has every step. [Connect turbo](/connect-turbo) sets up your team and CI, and [Sign artifacts](/sign-artifacts) explains the signature key.
