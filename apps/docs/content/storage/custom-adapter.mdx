To store artifacts in a backend without an S3 API (such as Google Cloud Storage or local disk), return any [Files SDK adapter](https://files-sdk.dev) from `apps/api/src/custom-adapter.ts`. A custom adapter takes highest priority, ahead of Cloudflare bindings and `S3_*` variables.

## The adapter hook

`apps/api/src/custom-adapter.ts` exports a single factory function that receives the runtime environment and returns an `Adapter` (or `undefined` to fall back to built-in backend resolution):

```ts apps/api/src/custom-adapter.ts
import type { CustomAdapter } from './utils/storage';

export const customAdapter: CustomAdapter = () => undefined;
```

`env` contains Worker bindings, variables, and secrets on Cloudflare, and `process.env` on other platforms. Because the hook runs per request, read configuration from `env` inside the function rather than at module scope. Nitro bundles anything imported by `custom-adapter.ts`, so import only the adapter you need.

## Adapter requirements

Before adopting a Files SDK adapter, confirm it meets three requirements:

- **User metadata support:** The server stores `x-artifact-duration` and `x-artifact-tag` in object metadata. Adapters that reject custom metadata (such as Vercel Blob) will fail every upload.
- **`lastModified` timestamps in `list()`:** The daily expiry task deletes any object whose age cannot be determined. Adapters that omit `lastModified` (such as Netlify Blobs) will have their entire cache wiped on each expiry run unless you disable scheduled expiry.
- **Target runtime compatibility:** Some adapters depend on Node.js SDKs that do not run on Cloudflare Workers. Verify runtime support on the adapter's documentation page before deploying.

## Example: Local filesystem

For a single-node server with a persistent disk, you can use the built-in `files-sdk/fs` adapter (note that Files SDK treats `fs` as a local/single-machine adapter with no replication):

<Steps>
    <Step title="Return the fs adapter when CACHE_DIR is set">
        `files-sdk` is already installed in `apps/api`, so no extra package is required:

        ```ts apps/api/src/custom-adapter.ts
        import { fs } from 'files-sdk/fs';

        import type { CustomAdapter } from './utils/storage';

        export const customAdapter: CustomAdapter = (env) =>
            typeof env.CACHE_DIR === 'string' ? fs({ root: env.CACHE_DIR }) : undefined;
        ```
    </Step>
    <Step title="Build for Node.js">
        ```sh
        NITRO_PRESET=node_server pnpm build
        ```
    </Step>
    <Step title="Start the server">
        ```sh
        cd apps/api
        CACHE_DIR=/var/lib/turborepo-cache TURBO_TOKEN='<your-token>' PORT=3000 pnpm start
        ```
    </Step>
    <Step title="Test locally, then add TLS">
        Test with `TURBO_API=http://localhost:3000` using the [remote-hit check](/connect-turbo#check-that-hits-come-from-the-server). Before sharing the server across machines, [serve it over HTTPS](/deploy/node#serve-it-over-https).
    </Step>

</Steps>

Artifacts are written to `<CACHE_DIR>/<team>/<hash>` alongside a `<hash>.meta.json` metadata file.

## Example: Google Cloud Storage

Install the Google Cloud Storage SDK in `apps/api`:

```sh
pnpm --filter @turborepo-remote-cache/api add @google-cloud/storage
```

Return the `gcs` adapter from `apps/api/src/custom-adapter.ts`:

```ts apps/api/src/custom-adapter.ts
import { gcs } from 'files-sdk/gcs';

import type { CustomAdapter } from './utils/storage';

export const customAdapter: CustomAdapter = (env) =>
    typeof env.GCS_BUCKET === 'string' ? gcs({ bucket: env.GCS_BUCKET }) : undefined;
```

Credentials are resolved automatically via Google Cloud Application Default Credentials (ADC).
