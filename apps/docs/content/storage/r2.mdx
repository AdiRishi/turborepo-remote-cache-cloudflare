---
title: Cloudflare R2
description: Configure the default R2 bucket binding on Cloudflare Workers and control bucket naming and geographic placement.
---

Cloudflare R2 is the default artifact store on Cloudflare Workers. Each artifact is stored as a single object under `<team>/<hash>` in the bucket bound as `R2_STORE`, with zero egress fees and no credentials to rotate.

## Use a different bucket

`apps/api/wrangler.jsonc` binds `turborepo-cache` by default:

```jsonc apps/api/wrangler.jsonc
{
    "r2_buckets": [
        {
            "binding": "R2_STORE",
            "bucket_name": "turborepo-cache",
            "preview_bucket_name": "turborepo-cache-preview",
        },
    ],
}
```

Change `bucket_name` and redeploy to point at another bucket (`wrangler deploy` creates the bucket if it doesn't already exist). Leave `"binding": "R2_STORE"` unchanged, since that's the binding name the server looks for.

## Choose where the bucket lives

When Wrangler auto-creates a bucket on first deploy, Cloudflare places it near the machine executing that deploy. To pin the bucket close to your CI runners or primary engineering region, create it ahead of time with a location hint:

```sh
cd apps/api
pnpm exec wrangler r2 bucket create turborepo-cache --location enam
```

See Cloudflare's [R2 data location hints](https://developers.cloudflare.com/r2/reference/data-location/#location-hints) for valid values. A bucket's location is immutable after creation; to move an existing cache, create a new bucket in the target region and update `bucket_name` in `wrangler.jsonc`.

## Access R2 from outside Cloudflare

Deployments on Node.js, Bun, Deno, Vercel, Netlify, or AWS Lambda can still store artifacts in R2 via its S3-compatible endpoint. See [S3-compatible storage (Cloudflare R2)](/storage/s3#cloudflare-r2).
