Set `S3_BUCKET`, `S3_ENDPOINT`, and credentials to back your remote cache with any S3-compatible object store. Credentials must allow reading, writing, listing, and deleting objects (listing and deletion are required for scheduled expiry and storage metrics).

See [Server configuration](/configuration#s3-variables) for the full list of `S3_*` variables and defaults.

## Amazon S3

```sh
S3_BUCKET=my-turborepo-cache
S3_ENDPOINT=https://s3.us-east-1.amazonaws.com
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=<access-key-id>
S3_SECRET_ACCESS_KEY=<secret-access-key>
```

Required IAM permissions on the bucket: `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`, and `s3:ListBucket`.

To authenticate with an IAM role (such as on [AWS Lambda](/deploy/aws-lambda) or ECS), leave `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` unset. The server falls back to `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, and `AWS_REGION` from the process environment. Local `~/.aws` profiles and SSO sessions are not read.

## Cloudflare R2

Create an [R2 API token](https://developers.cloudflare.com/r2/api/tokens/) with Object Read & Write permissions on your bucket, then set:

```sh
S3_BUCKET=turborepo-cache
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
S3_REGION=auto
S3_ACCESS_KEY_ID=<access-key-id>
S3_SECRET_ACCESS_KEY=<secret-access-key>
```

If your server runs on Cloudflare Workers, bind [`R2_STORE`](/storage/r2) directly instead. Native bindings avoid managing API tokens and stream without extra hops.

## MinIO and self-hosted stores

Self-hosted S3 stores typically don't resolve virtual-hosted bucket subdomains (`<bucket>.<endpoint>`). Enable path-style URLs with `S3_FORCE_PATH_STYLE=true`:

```sh
S3_BUCKET=turborepo-cache
S3_ENDPOINT=http://minio.internal:9000
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=<access-key>
S3_SECRET_ACCESS_KEY=<secret-key>
S3_FORCE_PATH_STYLE=true
```

If every cache lookup returns a miss on a new self-hosted S3 setup, check `S3_FORCE_PATH_STYLE` first.

## Using S3 on Cloudflare Workers

Cloudflare bindings take priority over `S3_*` variables. Remove the `r2_buckets` entry from `apps/api/wrangler.jsonc`, add `S3_BUCKET`, `S3_ENDPOINT`, and `S3_REGION` under `vars`, and store your credentials as Worker secrets:

```sh
cd apps/api
pnpm exec wrangler secret put S3_ACCESS_KEY_ID
pnpm exec wrangler secret put S3_SECRET_ACCESS_KEY
```

## Memory usage on large uploads

The S3 adapter buffers each uploaded artifact in memory before issuing a single `PutObject` request. On memory-constrained runtimes (like Workers or small containers), very large artifacts can hit memory limits even when under the platform's HTTP body cap. Review [Platforms](/deploy#artifact-size-limits) when sizing your runtime.
