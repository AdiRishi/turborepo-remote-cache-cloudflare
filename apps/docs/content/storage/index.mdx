title: Storage backends

Artifact storage is powered by [Files SDK](https://files-sdk.dev). The server ships with three built-in backends and a hook for any other Files SDK adapter.

| Backend                                   | Configuration                               | Supported platforms    |
| ----------------------------------------- | ------------------------------------------- | ---------------------- |
| [Cloudflare R2](/storage/r2)              | `R2_STORE` Worker binding                   | Cloudflare Workers     |
| [Cloudflare KV](/storage/kv)              | `KV_STORE` Worker binding                   | Cloudflare Workers     |
| [S3-compatible bucket](/storage/s3)       | `S3_BUCKET`, `S3_ENDPOINT`, and credentials | All platforms          |
| [Custom adapter](/storage/custom-adapter) | Export in `apps/api/src/custom-adapter.ts`  | Depends on the adapter |

## Recommendations

- **On Cloudflare Workers:** Stick with **R2**. It's bound by default, requires no API keys, has zero egress fees, and handles any payload size Workers accepts. Use Workers KV only if every artifact stays under 25 MiB and eventual consistency (60s+ global propagation) is acceptable.
- **On any other platform:** Use an **S3-compatible bucket** (AWS S3, Cloudflare R2 over S3, MinIO, Tigris, Backblaze B2, etc.). Write a custom adapter only for storage without an S3 API, such as Google Cloud Storage or local disk.

## How the server picks a backend

On each request, the server selects the first configured backend in this precedence order:

1. The adapter returned by `apps/api/src/custom-adapter.ts` (if non-`undefined`)
2. The `KV_STORE` binding
3. The `R2_STORE` binding
4. The `S3_*` environment variables (when `S3_BUCKET` is set)

Notice that Cloudflare bindings always take precedence over `S3_*` variables. If you want a Worker to talk to an external S3 bucket instead of R2, remove the `r2_buckets` binding from `apps/api/wrangler.jsonc`.

If no backend is configured, cache requests fail with `500` and log:

```text
Invalid server configuration: no artifact storage. Bind KV_STORE or R2_STORE on Cloudflare, set S3_BUCKET and S3_ENDPOINT, or return an adapter from src/custom-adapter.ts.
```

That detail is omitted from HTTP responses, so check your platform logs if you see `500` errors on a fresh deploy.

## Switching backends

The server only reads from the active backend. Switching to a new bucket or adapter starts with an empty cache: tasks miss once, rebuild, and populate the new store. Existing objects in the old backend remain untouched until you delete them.
