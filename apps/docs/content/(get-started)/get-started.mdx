This guide uses the recommended setup: Cloudflare Workers, R2 artifact storage, and a D1 database for usage stats. You need a Cloudflare account, a GitHub or GitLab account, and an existing Turborepo project with a cacheable build task.

Prefer a terminal? [Deploy to Cloudflare](/deploy/cloudflare) covers Wrangler. For another host, [choose a platform](/deploy).

## Prepare your account and token

1. Open **R2 Object Storage** in the [Cloudflare dashboard](https://dash.cloudflare.com/) and enable R2 if you have not used it before. Review [R2 pricing](https://developers.cloudflare.com/r2/pricing/) before enabling it.
2. Generate a token and save it in your secret manager:

    ```sh
    openssl rand -hex 32
    ```

    Use this same value for the Worker and every client. Anyone with the token can read and write every team's artifacts.

The deployment also serves a public dashboard that shows team names and usage. To keep those private, [restrict dashboard access](/dashboard#restrict-access) before connecting your projects.

If bucket location matters, [create the bucket first](/storage/r2#choose-where-the-bucket-lives). The button otherwise creates it during deployment.

1. Select **Deploy to Cloudflare** and sign in.
2. Connect your GitHub or GitLab account. Cloudflare copies this repository into your account and connects it to Workers Builds.
3. Keep the build command `pnpm run build` and deploy command `pnpm run deploy`. Both run from the repository root.
4. Wait for deployment to finish. It creates the Worker, the `turborepo-cache` R2 bucket, and the `turborepo-cache-stats` D1 database.
5. Open the Worker under **Workers & Pages**. Under **Settings** > **Variables and Secrets**, add a secret named `TURBO_TOKEN` with the value you saved.
6. Copy the Worker's URL, such as `https://turborepo-remote-cache.<your-subdomain>.workers.dev`.

Until you set the secret, cache requests return `500`. Your copy does not automatically receive upstream releases. [Update your deployment](/update) explains how to maintain it.

## Check the server

Replace the example URL and token in these commands:

```sh
export TURBO_API='https://turborepo-remote-cache.<your-subdomain>.workers.dev'
export TURBO_TOKEN='replace-with-your-saved-token'
curl --fail "$TURBO_API/ping"
curl --fail -H "Authorization: Bearer $TURBO_TOKEN" "$TURBO_API/v8/artifacts/status"
```

The first request returns `pong`. The second returns `{"status":"enabled"}`. A `401` means the token does not match the Worker's secret. A `500` means the server needs attention. [Troubleshooting](/troubleshooting) shows what to check.

## Verify your first remote hit

In the same terminal, change to the Turborepo project whose builds you want to cache. This is your application repository, not the cache server's checkout. Leave `TURBO_API` without a trailing slash and choose a team name:

```sh
export TURBO_TEAM='my-team'
```
