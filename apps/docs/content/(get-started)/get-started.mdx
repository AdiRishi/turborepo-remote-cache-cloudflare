We'll deploy the server with one button, give it a token, and run a build twice. The second time, `turbo` doesn't build anything. It replays the whole build from your Worker.

You need a Cloudflare account, a GitHub or GitLab account, and a Turborepo repository with a cacheable `build` task.

Prefer a terminal? [Deploy with Wrangler](/deploy/cloudflare) instead. Running somewhere other than Cloudflare? [Choose a platform](/deploy).

## Before you deploy

1. Turn on R2. If your account has never used it, open **R2 Object Storage** in the [Cloudflare dashboard](https://dash.cloudflare.com/) and follow the steps there. The [free tier](https://developers.cloudflare.com/r2/pricing/) includes 10 GB a month.
2. Generate a token, and keep it somewhere safe:

    ```sh
    openssl rand -hex 32
    ```

    Your Worker and every `turbo` client share this one token. Anyone who has it can read and write every artifact on the server, so treat it like a password.

## Deploy your copy

1. Select **Deploy to Cloudflare** and sign in to Cloudflare.
2. Connect your GitHub or GitLab account. Cloudflare copies this repository into it and creates a Worker that builds from the copy.
3. Keep the build command, `pnpm run build`, and the deploy command, `pnpm run deploy`. Both run from the repository root, because the server depends on other packages in the workspace.
4. Wait for the first deploy to finish. It creates the `turborepo-remote-cache` Worker, the `turborepo-cache` R2 bucket, and the `turborepo-cache-stats` D1 database for the [dashboard](/dashboard).
5. Go to **Workers & Pages**, select the Worker, and open **Settings** > **Variables and Secrets**. Add a secret named `TURBO_TOKEN` with your token as its value.
6. Copy the Worker's URL, such as `https://turborepo-remote-cache.<your-subdomain>.workers.dev`.

Until `TURBO_TOKEN` is set, every cache request gets a `500`. The deploy worked. The server just won't serve anyone without a token.

:::tip
R2 creates the bucket near the machine that runs the first deploy. To pick its location, create the bucket before you deploy. [Cloudflare R2](/storage/r2#choose-where-the-bucket-lives) shows how.
:::

## Check the server

Put your Worker's URL and token in the terminal, then knock on the door:

```sh
export TURBO_API='https://turborepo-remote-cache.<your-subdomain>.workers.dev'
export TURBO_TOKEN='<your token>'
curl "$TURBO_API/ping"
curl -H "Authorization: Bearer $TURBO_TOKEN" "$TURBO_API/v8/artifacts/status"
```

The first request answers `pong`, and needs no token. The second answers `{"status":"enabled"}`. A `401` means the token doesn't match the Worker's secret. For anything else, see [Turbo cannot connect](/troubleshooting#turbo-cannot-connect).

## Get your first remote hit

In the same terminal, switch to your Turborepo repository, so the URL and token come with you. Then pick a team name. Any name works, as long as every machine that shares builds uses the same one:

```sh
export TURBO_TEAM=my-team
```

## See it on the dashboard

Open your Worker's URL in a browser. The [dashboard](/dashboard) at the root already counts the hits you just made and the time they saved.

The dashboard is public, so anyone with the URL can see your team names and usage. [Restrict access](/dashboard#restrict-access) before you share the URL.

## Where to next
