---
title: Artifact signing
description: Verify remote cache downloads with HMAC-SHA256 signatures so compromised tokens cannot poison builds.
---

When artifact signing is enabled, `turbo` signs every uploaded artifact with a shared HMAC-SHA256 key and verifies the `x-artifact-tag` header on every download. The cache server stores and returns the signature untouched without ever seeing your signing key.

This separates **access control** from **build trust**: `TURBO_TOKEN` authorizes HTTP requests to the server, while `TURBO_REMOTE_CACHE_SIGNATURE_KEY` proves an artifact came from a trusted machine. Even if `TURBO_TOKEN` is compromised, an attacker cannot inject forged build outputs into developer laptops or CI.

## Enable signing

<Steps>
    <Step title="Enable signature verification in turbo.json">
        Add `"signature": true` under `remoteCache` in your root `turbo.json`:

        ```json turbo.json
        {
            "remoteCache": {
                "signature": true
            }
        }
        ```
    </Step>
    <Step title="Generate a signing key">
        Generate a separate 32-byte key (never reuse `TURBO_TOKEN`) and save it in your team's secret manager:

        ```sh
        openssl rand -hex 32
        ```

        Use at least 32 bytes. Shorter keys still work today, but Turborepo's [`longerSignatureKey`](https://turborepo.dev/docs/reference/configuration#longersignaturekey) future flag requires 32 bytes or more.
    </Step>
    <Step title="Distribute the key to clients and CI">
        Set `TURBO_REMOTE_CACHE_SIGNATURE_KEY` on every developer machine and CI job that reads or writes the cache:

        ```sh
        export TURBO_REMOTE_CACHE_SIGNATURE_KEY='<your-signing-key>'
        ```

        In CI, store it as a secret alongside `TURBO_TOKEN`.
    </Step>
    <Step title="Verify remote hits">
        Run the [remote-hit check](/connect-turbo#check-that-hits-come-from-the-server) to confirm signed artifacts upload and replay cleanly.
    </Step>

</Steps>

## How unverified artifacts behave

`turbo` treats any signature mismatch or missing signature as a cache miss rather than failing the build:

- Artifacts uploaded before enabling signatures will miss once and be overwritten with signed copies on the next run.
- A machine configured with the wrong key misses on all signed artifacts and rebuilds locally.
- A machine with no signing key set cannot sign uploads, so it skips uploading artifacts altogether.

## Rotating the signing key

Roll out the new `TURBO_REMOTE_CACHE_SIGNATURE_KEY` across CI and developer machines together. During a split rollout, machines on the old key and machines on the new key ignore each other's artifacts and fall back to rebuilding until every environment shares the new key.

See [Turborepo's artifact integrity docs](https://turborepo.dev/docs/core-concepts/remote-caching#artifact-integrity-and-authenticity-verification) for additional client details.
