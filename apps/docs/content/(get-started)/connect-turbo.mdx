A cached build is only worth something if the next machine can find it. Give every laptop and CI job the same URL, token, and team, and they all share one cache.

<a id="turbojson" />
<a id="choose-where-to-set-them" />

## Commit the URL and team

Add `remoteCache` to the root `turbo.json` of your repository, beside your existing settings:

```json turbo.json
{
    "remoteCache": {
        "apiUrl": "https://cache.example.com",
        "teamSlug": "my-team"
    }
}
```

Use the server's origin, with no trailing slash and no `/v8`. The team is any name you like, as long as machines that share builds use the same one. Teams keep artifacts apart, but [one token opens every team](/how-it-works#one-token-opens-every-team).

Commit the change. Every clone now knows where the cache is, and each machine needs only the token:

```sh
export TURBO_TOKEN='<your token>'
```

Keep the token out of Git. `TURBO_API` and `TURBO_TEAM` in a machine's environment win over `turbo.json`, so clear any stale ones if a machine talks to the wrong server.

<a id="turbo-login---manual" />

### Or log in with turbo

`turbo login --manual` asks for each value and checks the token against your server:

```sh
npm exec -- turbo login --manual
```

Answer its prompts:

1. At **Remote Cache URL**, enter the server's URL.
2. At **How do you want to specify your team?**, choose **slug** and enter the team name. Choose **id** only for a name that starts with `team_`.
3. At **Enter token**, paste the token.

`turbo` saves the token in your user configuration and writes the URL and team to the root `turbo.json`. Commit that change, and everyone else only has to log in.

[Client configuration](/client-configuration) lists every other place `turbo` reads these values from.

## Set up CI

Store the token as a secret in your CI provider and pass it to every step that runs `turbo`. The URL and team come from the committed `turbo.json`. If you didn't commit them, set `TURBO_API` and `TURBO_TEAM` as well.

<Tabs>
<Tab title="GitHub Actions">

Add a repository secret named `TURBO_TOKEN` under **Settings** > **Secrets and variables** > **Actions**, then pass it to the job:

```yaml .github/workflows/ci.yml
jobs:
    build:
        runs-on: ubuntu-latest
        env:
            TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
        steps:
            - uses: actions/checkout@v7
            # Install Node.js and your dependencies here.
            - run: npm exec -- turbo run build
```

</Tab>
<Tab title="GitLab CI">

Add a masked `TURBO_TOKEN` variable under **Settings** > **CI/CD** > **Variables**. GitLab passes project variables to every job, so the job only has to run `turbo`:

```yaml .gitlab-ci.yml
build:
    image: node:24
    script:
        # Install your dependencies here.
        - npm exec -- turbo run build
```

</Tab>
<Tab title="Other CI">

Read the token from the provider's secret store before the step that runs `turbo`:

```sh
export TURBO_TOKEN="$CACHE_TOKEN_SECRET"
npm exec -- turbo run build
```

</Tab>
</Tabs>

## Sign artifacts

Signing is optional, and we recommend it. With signatures on, `turbo` rejects any artifact your own machines didn't sign, so a leaked token can't slip a build onto your laptops or CI. [Sign artifacts](/sign-artifacts) takes one setting and one shared key.
