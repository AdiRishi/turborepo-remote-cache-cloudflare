Start with a deployed server and its `TURBO_TOKEN`. These steps configure your application repository, not the cache server's repository.

<a id="turbojson" />
<a id="choose-where-to-set-them" />

## Configure your project

Add `remoteCache` to your existing `turbo.json`. Keep your other settings:

```json turbo.json
{
    "remoteCache": {
        "apiUrl": "https://cache.example.com",
        "teamSlug": "my-team"
    }
}
```

Use the server's origin without a trailing slash or `/v8` path. Choose any team name, and use the same name everywhere that should share artifacts. Teams separate object names, not permissions. The server's token grants access to all teams.

Commit the URL and team. Give each developer the token through your secret manager, then set it in the environment that runs `turbo`:

```sh
export TURBO_TOKEN='replace-with-your-server-token'
```

Keep the token out of `turbo.json` and version control. Environment variables such as `TURBO_API` and `TURBO_TEAM` override the committed settings. Remove old values if a client connects to the wrong server or team.

<a id="turbo-login---manual" />

### Log in interactively

As an alternative to exporting the token, run:

```sh
pnpm exec turbo login --manual
```

Enter your server's URL, choose **slug**, enter the team name, and paste the token. Turbo saves the token in your user configuration and writes the URL and team to the root `turbo.json`. Review and commit those project settings.

For other configuration methods, see [Client configuration](/client-configuration).

## Connect CI

Store `TURBO_TOKEN` in your CI provider's secret store and expose it to the steps that run Turbo. The URL and team come from the committed `turbo.json`.

For GitHub Actions, add a repository secret named `TURBO_TOKEN`, then add `env` to the build step in your existing workflow, after Node.js and dependencies are installed:

```yaml
- name: Build
  run: pnpm exec turbo run build
  env:
      TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
```

For GitLab, add a masked `TURBO_TOKEN` under **Settings** > **CI/CD** > **Variables**. Other CI providers need the same environment variable.

If you do not commit the URL and team, also set `TURBO_API` and `TURBO_TEAM` in CI. Untrusted pull requests must not receive the token, because it grants write access to the cache.
