Every laptop and CI runner that shares the same server URL, `TURBO_TOKEN`, and team slug shares one remote cache. The cleanest setup commits the non-secret URL and team in `turbo.json` and distributes only `TURBO_TOKEN` through environment variables or a secret manager.

<a id="turbojson" />
<a id="choose-where-to-set-them" />

## Configure `turbo.json`

Add `remoteCache` to your repository's root `turbo.json`:

```json turbo.json
{
    "remoteCache": {
        "apiUrl": "https://cache.example.com",
        "teamSlug": "my-team"
    }
}
```

Use your server's bare HTTPS origin with no trailing slash and no `/v8` suffix. `teamSlug` can be any identifier you want; machines sharing artifacts just need to agree on the same value. Keep in mind that teams separate artifact namespaces rather than permissions (see [Security model and trade-offs](/introduction#one-token-opens-every-team)).

Commit `turbo.json`, then export `TURBO_TOKEN` in each developer's shell profile (or load it via direnv / your secret manager):

```sh
export TURBO_TOKEN='<your-token>'
```

Never commit `TURBO_TOKEN` to Git. Note that `TURBO_API` and `TURBO_TEAM` environment variables override `turbo.json`, so unset any stale values if `turbo` talks to the wrong host.

<a id="turbo-login---manual" />

### Alternative: `turbo login --manual`

If you prefer storing credentials in Turborepo's user config instead of exporting `TURBO_TOKEN` in your shell, run:

```sh
npm exec -- turbo login --manual
```

When prompted:

1. **Remote Cache URL:** Enter your server's origin (e.g. `https://cache.example.com`).
2. **How do you want to specify your team?** Pick **slug** and enter your team name (use **id** only for IDs prefixed with `team_`).
3. **Enter token:** Paste your `TURBO_TOKEN`.

Turborepo validates the token against your server, writes the token to your local user config, and updates `turbo.json` with the URL and team.

For all configuration sources and precedence rules, see [Client configuration](/client-configuration).

## Configure CI

Store `TURBO_TOKEN` as a secret in your CI provider and expose it to any step that invokes `turbo`. Because `apiUrl` and `teamSlug` live in `turbo.json`, CI jobs only need the token (if you didn't commit `remoteCache` in `turbo.json`, pass `TURBO_API` and `TURBO_TEAM` as well).

<Tabs>
<Tab title="GitHub Actions">

Create a repository secret named `TURBO_TOKEN` under **Settings** > **Secrets and variables** > **Actions** and pass it into your workflow:

```yaml .github/workflows/ci.yml
jobs:
    build:
        runs-on: ubuntu-latest
        env:
            TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
        steps:
            - uses: actions/checkout@v7
            # Install Node.js and dependencies here
            - run: npm exec -- turbo run build
```

</Tab>
<Tab title="GitLab CI">

Add a masked `TURBO_TOKEN` variable under **Settings** > **CI/CD** > **Variables**. GitLab injects project variables into jobs automatically:

```yaml .gitlab-ci.yml
build:
    image: node:24
    script:
        # Install dependencies here
        - npm exec -- turbo run build
```

</Tab>
<Tab title="Other CI">

Expose `TURBO_TOKEN` from your CI provider's secret store before calling `turbo`:

```sh
export TURBO_TOKEN="$CACHE_TOKEN_SECRET"
npm exec -- turbo run build
```

</Tab>
</Tabs>

## Enable artifact signing

For any cache shared by multiple developers or CI runners, enable [Artifact signing](/sign-artifacts). It takes one flag in `turbo.json` and a shared signing key, ensuring `turbo` rejects any artifact that wasn't produced by your own machines even if `TURBO_TOKEN` leaks.
