`turbo` already refuses to build the same thing twice on your laptop. A remote cache spreads that memory across your whole team. Once any laptop or CI runner builds a task, every other machine with the same inputs downloads the result and skips the work.

This project is that remote cache. It's an open-source server you deploy to your own Cloudflare account with one button, then point `turbo` at with a few lines of `turbo.json`.

<CacheFlow />

## Stop building the same thing twice

- **CI stops rebuilding the world.** A pull request rebuilds the packages it changed and the ones that depend on them. Everything else replays from the cache.
- **A fresh clone is ready in seconds.** A new teammate, a new laptop, or a throwaway worktree downloads its builds instead of making them.
- **Your coding agents stop burning minutes.** An agent that runs the test suite fifty times an afternoon replays every task whose inputs it didn't touch.

## Know the trade-offs

<a id="one-token-opens-every-team" />

- **One token opens every team.** Anyone with the token reads and writes every team's artifacts. If two groups must stay apart, give each its own deployment.
- **Your copy is yours.** The button copies this repository into your account, and the copy doesn't update itself. [Merging a new release](/update) is a `git merge` away.
- **The dashboard is public until you lock it.** Anyone with the URL sees your team names and usage. [Restrict access](/dashboard#restrict-access) before you share it.
- **Serverless hosts cap artifact size.** Vercel, Netlify, and AWS Lambda top out around 5 MB per upload, while Cloudflare Workers takes 100 MB or more. [Compare platforms](/deploy#artifact-size-limits) before you pick one.
