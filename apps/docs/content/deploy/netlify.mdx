:::warning[~4.5 MB payload limit]
Netlify Functions cap buffered payloads at 6 MB and Base64-encode binary bodies, leaving roughly 4.5 MB for each artifact. Larger outputs will fail to upload. Check [Artifact size limits](/deploy#artifact-size-limits) before choosing Netlify.
:::

## Create the site

Start from your fork of this repository (review [Build from source](/deploy#build-from-source) first):

<Steps>
    <Step title="Import your fork into Netlify">
        Leave **Base directory** empty so Netlify installs dependencies across the full pnpm workspace from the repository root, and set **Package directory** to `apps/api`.
    </Step>
    <Step title="Configure build and publish settings">
        - **Build command:** `pnpm exec turbo run build --filter=@turborepo-remote-cache/api`
        - **Publish directory:** `apps/api/dist`

        Turborepo builds the [dashboard](/dashboard) before the server, and Nitro auto-detects the `netlify` preset (set `NITRO_PRESET=netlify` if you prefer pinning it explicitly).
    </Step>
    <Step title="Add environment variables and deploy">
        Set `TURBO_TOKEN` and your [S3 storage variables](/storage/s3) in Netlify's site settings, then trigger a deploy.
    </Step>

</Steps>

## Verify and enable stats

Follow [Connect Turborepo](/connect-turbo) using your production site URL to confirm remote hits. Because Netlify Functions have a read-only filesystem, [configure a hosted stats database](/stats-database) to persist dashboard metrics.

## Scheduled expiry

The Netlify build does not run scheduled tasks automatically. Call `POST /internal/delete-expired-objects` once a day from an external scheduler. [Run expiry from a scheduler](/retention#run-expiry-from-a-scheduler) includes a ready-to-use GitHub Actions workflow.
