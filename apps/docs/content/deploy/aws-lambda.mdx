:::warning
Lambda caps a synchronous invocation payload at 6 MB. The event envelope and Base64 encoding reduce the size available for a binary artifact. Check the [artifact size limits](/deploy#artifact-size-limits) before choosing Lambda.
:::

## Build the handler

Clone your copy of the repository and install dependencies with `pnpm install --frozen-lockfile`. Use Node.js 24 or later and the pnpm version in `package.json`. Run the build from the repository root:

The [build setup](/deploy#build-from-source) covers the repository's own remote-cache settings.

```sh
NITRO_PRESET=aws_lambda pnpm build
```

1. Package the contents of `apps/api/.output/server` as the function code.
2. Choose a Node.js runtime, and set the handler to `index.handler`.
3. Give the function an HTTPS endpoint that `turbo` can reach, such as a Lambda function URL or an API Gateway HTTP API.

## Configure storage

Set these variables on the function:

```sh
TURBO_TOKEN=<your token>
S3_BUCKET=my-turborepo-cache
S3_ENDPOINT=https://s3.us-east-1.amazonaws.com
```

Leave the `S3_*` keys and `S3_REGION` unset to use the function's execution role. Lambda puts the role's credentials in `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN`, and its region in `AWS_REGION`, and the server reads all four. The role needs `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`, and `s3:ListBucket` on the bucket.

## Verify the deployment

[Connect turbo](/connect-turbo) to the production URL and verify a remote hit. For dashboard history, [configure a hosted stats database](/stats-database).

## The expiry task

The Lambda build doesn't schedule the expiry task. Call `POST /internal/delete-expired-objects` once a day from any scheduler that can send an HTTPS request with a header, such as a CI cron job. [Retention and expiry](/retention#run-expiry-from-a-scheduler) shows the request.
