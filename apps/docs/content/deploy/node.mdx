Run the server as a standalone HTTP process on any VM, container, or PaaS with an [S3-compatible bucket](/storage/s3) or a [custom Files SDK adapter](/storage/custom-adapter). Unlike serverless hosts, long-running servers impose no built-in artifact payload limit.

## Prepare the build environment

Requires Node.js 24+ and the pnpm version specified in `package.json`. Clone your fork, install dependencies from the repository root (`pnpm install --frozen-lockfile`), and review the `turbo.json` warning under [Build from source](/deploy#build-from-source).

## Configure environment variables

Export the bearer token and S3 credentials before starting the server (see [Server configuration](/configuration) for optional variables like `PORT`, `HOST`, and `S3_FORCE_PATH_STYLE`):

```sh
export TURBO_TOKEN='<your-token>'
export S3_BUCKET=turborepo-cache
export S3_ENDPOINT=https://s3.us-east-1.amazonaws.com
export S3_REGION=us-east-1
export S3_ACCESS_KEY_ID='<access-key-id>'
export S3_SECRET_ACCESS_KEY='<secret-access-key>'
```

## Build and start

Run the build from the repository root, then start the server from `apps/api`:

<Tabs>
<Tab title="Node.js">

```sh
NITRO_PRESET=node_server pnpm build
cd apps/api
pnpm start
```

</Tab>
<Tab title="Bun">

```sh
NITRO_PRESET=bun pnpm build
cd apps/api
bun run ./.output/server/index.mjs
```

</Tab>
<Tab title="Deno">

```sh
NITRO_PRESET=deno_server pnpm build
cd apps/api
deno run --allow-net --allow-read --allow-env --allow-write=.data .output/server/index.mjs
```

</Tab>
</Tabs>

The compiled `apps/api/.output` directory is self-contained. Copy it directly into a Docker image or onto your host without shipping `node_modules`.

By default, the server listens on `PORT` (`3000` if unset) and binds to `HOST`. Verify it's alive:

```sh
curl http://localhost:3000/ping
# pong
```

## Stats persistence

- **Node.js and Deno:** Dashboard stats are written to `.data/db.sqlite` relative to the server's working directory. Mount a persistent volume at `.data/` in containers so history survives restarts.
- **Bun:** Configure the `bun-sqlite` connector (or an external database) in `apps/api/nitro.config.ts`. See [Stats database](/stats-database).

## Serve it over HTTPS

Because `turbo` sends `TURBO_TOKEN` on every request, always terminate TLS in front of the server using a reverse proxy (Caddy, Nginx, Traefik) or load balancer, and set that HTTPS origin as `remoteCache.apiUrl` in `turbo.json`.

Once live over HTTPS, follow [Connect Turborepo](/connect-turbo) to verify remote hits.

## Scheduled expiry

The server runs `cache:delete-expired` in-process every day at 03:00 UTC. If the process is down at 03:00 UTC, that day's sweep is skipped until the next day (or an [on-demand trigger](/retention#run-expiry-on-demand)). Running multiple replicas behind a load balancer is safe: the first replica deletes expired objects and the rest become no-ops.
