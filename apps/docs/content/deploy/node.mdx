description: Run the server as a long-running Node.js, Bun, or Deno process with an S3-compatible bucket.
---

The server runs as one process and stores artifacts in an [S3-compatible bucket](/storage/s3) or through a [custom adapter](/storage/custom-adapter).

## Prepare the checkout

Use Node.js 24 or later and the pnpm version in `package.json` to build the server. Clone your copy of the repository and run `pnpm install --frozen-lockfile` from its root. Each build command below also runs from that root.

The [build setup](/deploy#build-from-source) covers the repository's own remote-cache settings.

## Configure the server

Before starting the server, export these values in the same terminal. Replace the token and credentials with your own:

```sh
export TURBO_TOKEN='replace-with-your-server-token'
export S3_BUCKET=turborepo-cache
export S3_ENDPOINT=https://s3.us-east-1.amazonaws.com
export S3_REGION=us-east-1
export S3_ACCESS_KEY_ID='replace-with-your-access-key'
export S3_SECRET_ACCESS_KEY='replace-with-your-secret-key'
```

## Build and start

<Tabs>
<Tab title="Node.js">

```sh
NITRO_PRESET=node_server pnpm build
cd apps/api
pnpm start
```

</Tab>
<Tab title="Bun">

```sh
NITRO_PRESET=bun pnpm build
cd apps/api
bun run ./.output/server/index.mjs
```

</Tab>
<Tab title="Deno">

```sh
NITRO_PRESET=deno_server pnpm build
cd apps/api
deno run --allow-net --allow-read --allow-env --allow-write=.data .output/server/index.mjs
```

</Tab>
</Tabs>

The build in `apps/api/.output` is self-contained. To deploy it, copy that directory to the machine or image that runs it.

On Node.js and Deno, the server keeps the [dashboard](/dashboard)'s stats in a SQLite file at `.data/db.sqlite`, relative to the directory it starts in. In a container, mount a volume there so the stats survive a restart.

For Bun, [configure the stats database](/stats-database) with the `bun-sqlite` connector.

The server listens on `PORT`, or on `3000` when `PORT` is unset. `HOST` sets the address it binds to. [Configuration](/configuration) lists every variable.

Check it with `curl http://localhost:3000/ping`, which answers `pong`.

## Serve it over HTTPS

`turbo` sends the token with every request. Run the server behind a reverse proxy or load balancer that terminates TLS, and set `TURBO_API` to the HTTPS address.

[Connect turbo](/connect-turbo) using that HTTPS address, then verify a remote hit.

## The expiry task

The server runs `cache:delete-expired` inside its own process, daily at 03:00 UTC. A server that is down at that time skips that day's run. When several copies run behind a load balancer, each one runs the task, and the later runs find nothing to delete.
