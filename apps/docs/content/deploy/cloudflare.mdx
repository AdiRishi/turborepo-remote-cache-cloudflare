---
title: Deploy to Cloudflare
description: Build and deploy the Worker from your own checkout, or deploy changes automatically from Git.
---

Wrangler builds the Worker from your checkout and creates its R2 bucket and stats database on the first deploy. For the one-button setup, use [Get started](/get-started).

## Before you begin

Turn on R2 in your Cloudflare account. Wrangler creates the bucket near the machine that runs the first deploy. To pick its location, [create it before you deploy](/storage/r2#choose-where-the-bucket-lives).

Generate a token for the Worker and your Turbo clients:

```sh
openssl rand -hex 32
```

## Build and deploy

You need [Node.js](https://nodejs.org) 24 or later and [pnpm](https://pnpm.io). Install the version in the repository's `packageManager` field, using the [pnpm installation guide](https://pnpm.io/installation).

1. Clone the repository and install its dependencies:

    ```sh
    git clone https://github.com/AdiRishi/turborepo-remote-cache-cloudflare.git
    cd turborepo-remote-cache-cloudflare
    pnpm install
    ```

2. Remove `remoteCache` from the root `turbo.json`, or point it at your own server. It sends this repository's builds to the maintainer's cache, and with `TURBO_TOKEN` in your shell, `turbo` would send your token there too.

3. Build the Worker and deploy it:

    ```sh
    pnpm build
    pnpm run deploy
    ```

    Wrangler opens a browser to sign you in to Cloudflare if you aren't signed in yet. On the first deploy, it creates the `turborepo-cache` R2 bucket and the `turborepo-cache-stats` D1 database for the [dashboard](/dashboard). When it finishes, it prints the Worker's URL, such as `https://turborepo-remote-cache.<your-subdomain>.workers.dev`.

4. Set the token:

    ```sh
    cd apps/api
    pnpm exec wrangler secret put TURBO_TOKEN
    ```

    Wrangler asks for the value. Paste your token.

## Check the deployment

`/ping` needs no token. Replace the URL with your Worker's URL:

```sh
export TURBO_API='https://turborepo-remote-cache.<your-subdomain>.workers.dev'
curl --fail "$TURBO_API/ping"
```

The Worker answers `pong`. Now check the token:

```sh
export TURBO_TOKEN='<your token>'
curl --fail -H "Authorization: Bearer $TURBO_TOKEN" "$TURBO_API/v8/artifacts/status"
```

The Worker answers `{"status":"enabled"}`. A `401` response means the token doesn't match `TURBO_TOKEN`.

[Connect turbo](/connect-turbo) to verify that your builds use the server.

## Deploy changes from Git

Pick one service to deploy pushes to your copy. If you set up both, both deploy the same commit.

### Workers Builds

If you used the Deploy to Cloudflare button, [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) is already set up. It deploys every push to your copy's production branch. Keep the build directory at the repository root, the build command at `pnpm run build`, and the deploy command at `pnpm run deploy`.

### GitHub Actions

The repository's [CI workflow](https://github.com/AdiRishi/turborepo-remote-cache-cloudflare/blob/master/.github/workflows/ci.yml) deploys pushes to `master` after checks and end-to-end tests pass. To use it in your copy:

1. Delete the `release`, `docs-cloudflare`, and `docs-github-pages` jobs. They publish this project's releases and documentation.
2. Add these repository secrets under **Settings** > **Secrets and variables** > **Actions**:
    - `CLOUDFLARE_API_TOKEN`: a token that can edit Workers, R2, and D1.
    - `CLOUDFLARE_ACCOUNT_ID`: your Cloudflare account ID.
    - `TURBO_TOKEN`: the same token your clients use. The workflow sets it as the Worker's secret on each deployment. If this secret is missing, the Worker's token becomes `SECRET`.
3. Remove `remoteCache` from the root `turbo.json`, or point it at your own server. The workflow passes `TURBO_TOKEN` to every `turbo` run, so without this step it sends your token to the maintainer's cache.
4. Push to `master`. If you use a different production branch, update the workflow's branch filters and deployment condition.

When a new release comes out, [Update your deployment](/update) shows how to merge it into your copy.
