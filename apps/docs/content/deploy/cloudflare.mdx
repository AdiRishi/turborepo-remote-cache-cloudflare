---
title: Deploy to Cloudflare
description: Build and deploy the Worker from your own checkout, or deploy changes automatically from Git.
---

Prefer to deploy from your terminal? Wrangler builds the Worker and creates its R2 bucket and stats database on the first deploy. This guide also covers deployment from Git. For the button-based setup, use [Get started](/get-started).

## Before you begin

Enable R2 in your Cloudflare account. To choose the bucket's location, [create it before deploying](/storage/r2#choose-where-the-bucket-lives). Otherwise, Wrangler creates it near the machine that runs the first deploy.

Generate a token for the Worker and your Turbo clients:

```sh
openssl rand -hex 32
```

## Build and deploy

You need [Node.js](https://nodejs.org) 24 or later and [pnpm](https://pnpm.io). Install pnpm using its [installation guide](https://pnpm.io/installation). Use the version in the repository's `packageManager` field.

1. Clone the repository and install its dependencies:

    ```sh
    git clone https://github.com/AdiRishi/turborepo-remote-cache-cloudflare.git
    cd turborepo-remote-cache-cloudflare
    pnpm install
    ```

2. Remove the root `turbo.json` file's `remoteCache` entry, or replace its URL and team with your own cache. It points at the maintainer's cache, so do this before supplying your token to builds.

3. Build the Worker and deploy it:

    ```sh
    pnpm build
    pnpm run deploy
    ```

    Wrangler opens a browser to sign you in to Cloudflare if you aren't signed in yet. On the first deploy, it creates the `turborepo-cache` R2 bucket and the `turborepo-cache-stats` D1 database for the [dashboard](/dashboard). When it finishes, it prints the Worker's URL, such as `https://turborepo-remote-cache.<your-subdomain>.workers.dev`.

4. Set the token:

    ```sh
    cd apps/api
    pnpm exec wrangler secret put TURBO_TOKEN
    ```

    Wrangler asks for the value. Paste your token.

## Check the deployment

`/ping` needs no token. Replace the URL with your Worker's URL:

```sh
export TURBO_API='https://turborepo-remote-cache.<your-subdomain>.workers.dev'
curl --fail "$TURBO_API/ping"
```

The Worker answers `pong`. Now check the token:

```sh
export TURBO_TOKEN='replace-with-your-saved-token'
curl --fail -H "Authorization: Bearer $TURBO_TOKEN" "$TURBO_API/v8/artifacts/status"
```

The Worker answers `{"status":"enabled"}`. A `401` response means the token doesn't match `TURBO_TOKEN`.

[Connect turbo](/connect-turbo) to verify that your builds use the server.

## Deploy changes from Git

The button sets up Workers Builds for you. If you prefer to keep builds and deployment in GitHub Actions, the repository includes a workflow for that too.

### Workers Builds

[Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) deploys pushes to the production branch of your copy. Keep the build directory at the repository root, the build command at `pnpm run build`, and the deploy command at `pnpm run deploy`. Set `TURBO_TOKEN` as a Worker secret.

If you also configure GitHub Actions below, both services can deploy the same commit. Choose the one you want to handle deployment.

### GitHub Actions

The repository's [CI workflow](https://github.com/AdiRishi/turborepo-remote-cache-cloudflare/blob/master/.github/workflows/ci.yml) deploys pushes to `master` after checks and end-to-end tests pass. To use it in your copy:

1. Delete the `release`, `docs-cloudflare`, and `docs-github-pages` jobs. They publish this project's releases and documentation.
2. Add these repository secrets under **Settings** > **Secrets and variables** > **Actions**:
    - `CLOUDFLARE_API_TOKEN`: a token that can edit Workers, R2, and D1.
    - `CLOUDFLARE_ACCOUNT_ID`: your Cloudflare account ID.
    - `TURBO_TOKEN`: the same token your clients use. The workflow sets it as the Worker's secret on each deployment.
3. Push to `master`. If you use a different production branch, update the workflow's branch filters and deployment condition.

If the repository secret `TURBO_TOKEN` is absent, the workflow deploys with `SECRET` as the token. Set the secret to use your own value.

The root `turbo.json` points this repository's builds at the maintainer's cache. Remove its `remoteCache` entry or point it at your own server before supplying your token to CI.

When a new release is available, [Update your deployment](/update) shows how to bring it into your copy while keeping your settings.
