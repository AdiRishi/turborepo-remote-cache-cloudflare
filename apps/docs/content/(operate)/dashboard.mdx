Every deployment serves a live analytics dashboard at `/` (for example, `https://turborepo-remote-cache.<your-subdomain>.workers.dev`). It refreshes automatically every minute and requires no login unless you put an access layer in front of it.

## Metrics

Use the range picker at the top to switch between the last **24 hours**, **7 days**, **30 days**, or **90 days**. Every metric compares the selected window against the preceding period of the same length, while the summary line beside the picker shows cumulative time saved since the first recorded run.

- **Time saved:** Total task duration replayed from cache (both remote hits from this server and local hits on client machines), derived from the cache events `turbo` reports after each run.
- **Share of task time cached:** Time saved divided by total task time (cached durations plus executed task durations reported on upload; tasks that execute without uploading are excluded).
- **Task breakdown:** Splits every task lookup into local hits, remote hits, and full misses, alongside the combined cache share.
- **Server hit rate:** Percentage of lookups reaching this server (after a local miss) that returned a cached artifact.
- **Saved per run & total runs:** Average time saved per `turbo` invocation and total run count.
- **Teams:** Per-team breakdown of runs, hit rate, time saved (with trend), storage footprint, and downloads, grouped by `teamId` or `slug`. Appears once more than one team reports activity.
- **Storage:** Current artifact count and total bytes stored, plus change over the selected window.
- **Clients:** Breakdown by CI provider, AI coding agent, `turbo` CLI version, and OS/architecture.

Cloudflare deployments provision a D1 stats database automatically. For other hosts, or to turn analytics off, see [Stats database](/stats-database).

## Restrict access

By default, `/` and `/stats` are publicly readable without a token, exposing team names and usage metrics to anyone with the URL.

To lock the dashboard down, place `/` and `/stats` behind an authentication proxy such as [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/) while leaving `/v8/*` accessible via `turbo`'s bearer token. Protect **both** routes; gating only `/` still leaves `/stats` readable.

## When storage numbers update

Storage size and artifact counts are recorded by the daily [expiry task](/retention) rather than incremented per upload, so a fresh deployment shows empty storage figures until expiry runs once.

To populate storage metrics immediately, [run expiry on demand](/retention#run-expiry-on-demand) (which also purges expired objects). On Netlify and AWS Lambda, configure an [external schedule](/retention#run-expiry-from-a-scheduler) so storage figures stay up to date.

## Read the stats as JSON

`GET /stats` returns the raw payload powering the dashboard with no authentication required. Pass `range=24h`, `7d`, `30d` (default), or `90d`:

```sh
curl "https://<your-server>/stats?range=7d"
```

When no stats database is configured, the response returns `"enabled": false`. Daily buckets are aligned to UTC midnight and all durations are in milliseconds.
