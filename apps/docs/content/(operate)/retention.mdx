---
title: Retention and expiry
description: Configure artifact retention, customize the daily cleanup schedule, or trigger expiry manually.
---

By default, cached artifacts are retained for `BUCKET_OBJECT_EXPIRATION_HOURS`, which defaults to `720` hours (30 days). Each day at 03:00 UTC, the `cache:delete-expired` task scans the bucket, removes objects older than that threshold (as well as any object without a `lastModified` timestamp), and records fresh storage totals for the dashboard.

Age is measured from the original upload time, not last download. Frequently hit artifacts still expire on schedule and are repopulated cleanly on the next build.

:::warning[Use a dedicated bucket or namespace]
`cache:delete-expired` deletes every expired object in the configured store, not just objects matching a prefix. Never share the cache bucket or KV namespace with unrelated data.
:::

## Change the retention window

On Cloudflare Workers, update `vars` in `apps/api/wrangler.jsonc` and redeploy:

```jsonc apps/api/wrangler.jsonc
{
    "vars": {
        "BUCKET_OBJECT_EXPIRATION_HOURS": 168,
    },
}
```

On all other platforms, set `BUCKET_OBJECT_EXPIRATION_HOURS` in the server's environment. The value must be a whole number of hours (`>= 1`). When using [Workers KV](/storage/kv#how-entries-expire), this value also sets each KV entry's TTL on write.

## Change or disable the schedule

Edit `scheduledTasks` in `apps/api/nitro.config.ts` using a UTC cron expression, then rebuild and redeploy:

```ts apps/api/nitro.config.ts
scheduledTasks: {
  '0 3 * * *': ['cache:delete-expired'],
},
```

Remove the entry to disable automatic cleanup altogether (note that KV entries will still expire via their write-time TTL). Check [Platforms](/deploy) to see which hosts run Nitro schedules natively.

## Run expiry on demand

Trigger cleanup manually with an authenticated `POST /internal/delete-expired-objects` request. Send `{}` to use the configured `BUCKET_OBJECT_EXPIRATION_HOURS`:

```sh
curl -X POST https://cache.example.com/internal/delete-expired-objects \
  -H "Authorization: Bearer <your-token>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```json
{ "deleted": 42 }
```

To override the retention window for a single run, pass `expireInHours` (`>= 0`). Passing `{"expireInHours": 0}` purges the entire cache. Omitting a valid JSON body or passing a negative number returns `400`.

## Run expiry from a scheduler

On platforms without built-in task scheduling (Netlify, AWS Lambda), invoke the internal endpoint daily from an external cron. For example, with GitHub Actions using a `CACHE_URL` repository variable and `TURBO_TOKEN` secret:

```yaml .github/workflows/cache-expiry.yml
on:
    schedule:
        - cron: '0 3 * * *'

jobs:
    expire:
        runs-on: ubuntu-latest
        steps:
            - run: |
                  curl --fail -X POST "${{ vars.CACHE_URL }}/internal/delete-expired-objects" \
                    -H "Authorization: Bearer ${{ secrets.TURBO_TOKEN }}" \
                    -H "Content-Type: application/json" \
                    -d '{}'
```
