Version 5 rebuilds the server on [Nitro](https://nitro.build) and [Files SDK](https://files-sdk.dev). Existing Cloudflare deployments keep their `TURBO_TOKEN` secret, `BUCKET_OBJECT_EXPIRATION_HOURS`, `R2_STORE`, and `KV_STORE` bindings, and existing R2 artifacts remain valid (including signatures).

For updates within v5, see [Updating your deployment](/update).

## Migrate your Wrangler configuration

Version 5 moves to a pnpm workspace with the server under `apps/api`:

| Version 4                            | Version 5                                      |
| ------------------------------------ | ---------------------------------------------- |
| `wrangler.jsonc`                     | `apps/api/wrangler.jsonc`                      |
| `src/`                               | `apps/api/src/`                                |
| `triggers.crons` in `wrangler.jsonc` | `scheduledTasks` in `apps/api/nitro.config.ts` |

1. Port your custom settings (bucket name, KV namespace, retention hours, routes) into `apps/api/wrangler.jsonc`. Omit `triggers` (Nitro generates the cron trigger from `scheduledTasks` at build time) and drop `ENVIRONMENT`, which v5 no longer reads.
2. Build and deploy from the repository root:

    ```sh
    pnpm install
    pnpm build
    pnpm run deploy
    ```

If you deploy via Workers Builds, update the build directory to the repository root with build command `pnpm run build` and deploy command `pnpm run deploy`.

## Breaking changes

The `turbo` CLI works out of the box with all v5 changes. Update any custom scripts or health checks that call the server directly:

- **Strict Remote Cache v8 compliance:**
    - Non-hexadecimal artifact hashes return `400`.
    - Invalid artifact headers return `400`.
    - Error responses use `{ "code": "...", "message": "..." }` JSON bodies.
    - `POST /v8/artifacts` now supports batch artifact metadata queries.
- **Internal endpoints:**
    - `POST /internal/delete-expired-objects` returns `{ "deleted": <count> }` instead of `{ "success": true }`. It still requires a JSON body (`{}` uses the configured retention window).
    - `POST /internal/populate-random-objects` and `GET /internal/count-objects` have been removed (`404`).
- **No Cloudflare Cache API layer:** v4 cached downloaded artifacts in Cloudflare's Cache API for 5 minutes and returned a `Cache-Control` header. v5 streams directly from storage without sending `Cache-Control`.

## Stored artifacts

| Backend | Compatibility after upgrading to v5                                                                                                                                                                                                                                                                       |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R2**  | Fully compatible. v5 reads v4 objects and their `x-artifact-tag` signatures without interruption.                                                                                                                                                                                                         |
| **KV**  | Readable, but without signatures, because v5 uses a new metadata layout. Clients with artifact signing enabled will treat v4 KV entries as misses once and overwrite them with v5 entries. The next daily expiry removes remaining v4 entries because their upload timestamp is absent in the new format. |
