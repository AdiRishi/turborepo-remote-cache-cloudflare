Because your server deploys from your own fork of this repository, it won't upgrade itself automatically. Pull in new releases by merging the release tag into your fork and redeploying. Your R2 bucket, stats database, and `TURBO_TOKEN` secret stay intact.

Upgrading from version 4? Follow [Upgrading from v4](/upgrade-from-v4) first.

## Before you merge

1. Check the [API changelog](https://github.com/AdiRishi/turborepo-remote-cache/blob/master/apps/api/CHANGELOG.md) for breaking configuration changes or stats database migrations.
2. Back up your stats database if the release includes a schema migration (rolling back application code does not revert migrations). Cached artifacts don't need backups, since `turbo` rebuilds anything missing.
3. Know which files hold your local customizations so you keep your side during conflict resolution:
    - `apps/api/wrangler.jsonc`: Worker name, bindings, resource IDs, custom routes, and `vars`
    - `apps/api/nitro.config.ts`: stats database connector and expiry schedule
    - `apps/api/src/custom-adapter.ts`: custom Files SDK storage adapter (if used)
    - `.github/workflows/ci.yml` and root `turbo.json`: your deployment workflow and remote cache settings

## Merge an upstream release

Add the upstream repository as a remote and fetch tags:

```sh
git remote add upstream https://github.com/AdiRishi/turborepo-remote-cache.git
git fetch upstream --tags
```

Server releases are tagged `@turborepo-remote-cache/api@<version>`. Merge your target version (for example, `5.3.0`):

```sh
git merge @turborepo-remote-cache/api@5.3.0
```

Resolve any conflicts in the customized files above by keeping your resource names, IDs, and settings while accepting upstream changes everywhere else. Review those files even after a clean merge to be sure nothing was overwritten.

:::note[Unrelated Git histories]
If Git exits with `refusing to merge unrelated histories`, your copy was created without shared Git ancestry (for example, via a template copy). Fork the upstream repository cleanly, check out the release tag, copy over your settings from the files listed above, and point Workers Builds or CI at the new fork. Future merges will apply cleanly.
:::

## Verify and deploy

<Steps>
    <Step title="Install and run checks">
        ```sh
        pnpm install --frozen-lockfile
        pnpm check
        ```
    </Step>
    <Step title="Commit and deploy">
        Commit the merge and deploy using your normal workflow: push to your production branch for Workers Builds or GitHub Actions, run `pnpm run deploy` for manual Cloudflare deploys, or follow your [platform guide](/deploy).
    </Step>
    <Step title="Smoke-test the live server">
        Confirm `/ping` and `/v8/artifacts/status` respond cleanly ([Check the deployment](/deploy/cloudflare#check-the-deployment)), run the [remote-hit check](/connect-turbo#check-that-hits-come-from-the-server), and open the dashboard. If stats stop recording, inspect `[stats]` entries in your [logs](/observability).
    </Step>

</Steps>
