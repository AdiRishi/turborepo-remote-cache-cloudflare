Analytics are stored through [Nitro's database layer](https://nitro.build/docs/database). Writes run asynchronously after each HTTP response is sent, so database latency never slows down `turbo` and a database error never fails a cache request. Without a database, artifact caching works identically and the dashboard shows that stats are disabled.

| Platform                                                                               | Default database behavior                                                                                          |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| [Cloudflare Workers](/deploy/cloudflare)                                               | Cloudflare D1 bound as `STATS_DB`. Auto-created as `turborepo-cache-stats` on first deploy.                        |
| [Node.js and Deno](/deploy/node)                                                       | Local SQLite file at `.data/db.sqlite` relative to the working directory. Mount a persistent volume in containers. |
| [Bun](/deploy/node)                                                                    | Configure the `bun-sqlite` connector or an external database in `apps/api/nitro.config.ts`.                        |
| [Vercel](/deploy/vercel), [Netlify](/deploy/netlify), [AWS Lambda](/deploy/aws-lambda) | None by default (read-only/ephemeral filesystem). Configure a hosted database below to enable dashboard history.   |

On Cloudflare, D1's free plan includes 100,000 rows written per day. The server writes roughly four rows per `turbo` run plus one per artifact upload or download. See [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) if your monorepo runs at higher volume.

## Configure a hosted database

Define the `default` database connection in `apps/api/nitro.config.ts`. For example, using [Turso](https://turso.tech) (`libsql`):

```ts apps/api/nitro.config.ts
// Add `database` inside the existing defineConfig call.
export default defineConfig({
    database: {
        default: {
            connector: 'libsql',
            options: {
                url: process.env.TURSO_URL,
                authToken: process.env.TURSO_AUTH_TOKEN,
            },
        },
    },
});
```

Tables are created automatically on first write. Supported [Nitro connectors](https://nitro.build/docs/database#connectors) are SQLite, libSQL, PostgreSQL, Neon, and PGlite (MySQL is not supported).

:::tip[Build-time environment evaluation]
Nitro serializes connector options into the build output. Any `process.env.*` reference in `nitro.config.ts` is evaluated during `pnpm build`, not at server startup.
:::

Rebuild and redeploy after updating `nitro.config.ts`, then check `GET /stats` to confirm `"enabled": true`. If stats remain disabled, see [Dashboard stats are unavailable](/troubleshooting#dashboard-stats-are-unavailable).

## Disable stats

- **Cloudflare Workers:** Remove the `d1_databases` block from `apps/api/wrangler.jsonc`.
- **Other platforms:** Set `database: {}` in `apps/api/nitro.config.ts`.

Rebuild and redeploy. Artifact caching continues unaffected while `/` and `/stats` report that analytics are disabled.
