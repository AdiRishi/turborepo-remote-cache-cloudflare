The server is a [Nitro](https://nitro.build) app. It builds for Cloudflare Workers by default, and the `NITRO_PRESET` variable selects another target. Every target serves the same API. Storage and the daily expiry task differ by platform.

## Build for a platform

From the repository root, set `NITRO_PRESET` and build the server:

```sh
NITRO_PRESET=node_server pnpm build --filter=@turborepo-remote-cache/server
```

| Platform           | `NITRO_PRESET`                    | Build output in `apps/server` | Guide                                     |
| ------------------ | --------------------------------- | ----------------------------- | ----------------------------------------- |
| Cloudflare Workers | `cloudflare_module` (the default) | `.output`                     | [Get started on Cloudflare](/get-started) |
| Node.js            | `node_server`                     | `.output`                     | [Node.js, Bun, and Deno](/deploy/node)    |
| Bun                | `bun`                             | `.output`                     | [Node.js, Bun, and Deno](/deploy/node)    |
| Deno               | `deno_server`                     | `.output`                     | [Node.js, Bun, and Deno](/deploy/node)    |
| Vercel             | `vercel`, detected on Vercel      | `.vercel/output`              | [Vercel](/deploy/vercel)                  |
| Netlify            | `netlify`, detected on Netlify    | `.netlify` and `dist`         | [Netlify](/deploy/netlify)                |
| AWS Lambda         | `aws_lambda`                      | `.output`                     | [AWS Lambda](/deploy/aws-lambda)          |

Nitro has presets for more platforms. This project tests the Cloudflare and Node.js builds end to end in CI.

## Storage on each platform

The `R2_STORE` and `KV_STORE` bindings exist only on Cloudflare Workers. Everywhere else, use an [S3-compatible bucket](/storage/s3) or a [custom adapter](/storage/custom-adapter).

## The expiry task on each platform

The `cache:delete-expired` task runs daily at 03:00 UTC. Each platform runs it differently:

| Platform                               | How the task runs                                                                 |
| -------------------------------------- | --------------------------------------------------------------------------------- |
| Cloudflare Workers                     | A cron trigger in the Worker's generated Wrangler configuration.                  |
| Node.js, Bun, and Deno                 | A scheduler inside the server process, so it runs while the server is up.         |
| Vercel                                 | A Vercel Cron Job.                                                                |
| Netlify, AWS Lambda, and other presets | Nothing. Call `POST /internal/delete-expired-objects` from an external scheduler. |

[Retention and expiry](/retention) shows how to call the endpoint.

## Request size limits

Platforms cap the size of a request, and serverless platforms also cap the response. An artifact larger than the cap can't be uploaded or downloaded, so its task never hits the remote cache:

| Platform               | Largest artifact                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| Cloudflare Workers     | 100 MB uploads on the Free and Pro plans, 200 MB on Business. Downloads have no limit.     |
| Node.js, Bun, and Deno | No platform limit. A proxy in front of the server can set one.                             |
| Vercel                 | 4.5 MB, the limit for a request or response body.                                          |
| Netlify                | About 4.5 MB. Netlify buffers up to 6 MB and Base64-encodes binary data inside that limit. |
| AWS Lambda             | 6 MB for a synchronous request or response.                                                |

Build outputs often exceed 4.5 MB. For a repository with large outputs, choose Cloudflare Workers or a long-running server.
