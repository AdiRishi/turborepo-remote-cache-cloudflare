For background on how `turbo` uses the cache, read the [Introduction](/introduction) first.

## Before you begin

- You need a Cloudflare account with R2 turned on. If your account has never used R2, open **R2 Object Storage** in the [Cloudflare dashboard](https://dash.cloudflare.com/) and follow the steps there. R2 has a [free tier](https://developers.cloudflare.com/r2/pricing/).
- Choose a token. Every `turbo` client sends it to the server, so make it long and random:

    ```sh
    openssl rand -hex 32
    ```

## Deploy with the button

<a href="https://deploy.workers.cloudflare.com/?url=https://github.com/AdiRishi/turborepo-remote-cache-cloudflare">
    <img
        src="https://deploy.workers.cloudflare.com/button"
        alt="Deploy to Cloudflare"
        width="184"
        height="39"
    />
</a>

1. Select **Deploy to Cloudflare** and sign in to Cloudflare.
2. Connect your GitHub or GitLab account. Cloudflare copies the repository into it and creates a Worker that builds from the copy.
3. Keep the build command, `pnpm run build`, and the deploy command, `pnpm run deploy`. The button deploys the whole repository because the server depends on another package in the workspace.
4. Wait for the first deploy to finish. Wrangler creates the `turborepo-cache` R2 bucket during that deploy.
5. In the dashboard, go to **Workers & Pages**, select the `turborepo-remote-cache` Worker, and open **Settings** > **Variables and Secrets**. Add a secret named `TURBO_TOKEN` with your token as its value.

Until `TURBO_TOKEN` is set, the server answers every cache request with a `500` error.

## Deploy with Wrangler

Use this path to deploy from your own machine. You need [Node.js](https://nodejs.org) 24 or later and [pnpm](https://pnpm.io). The repository pins its pnpm version, and `corepack enable` installs that version for you.

1. Clone the repository and install its dependencies:

    ```sh
    git clone https://github.com/AdiRishi/turborepo-remote-cache-cloudflare.git
    cd turborepo-remote-cache-cloudflare
    pnpm install
    ```

2. Sign in to Cloudflare:

    ```sh
    pnpm --filter @turborepo-remote-cache/server exec wrangler login
    ```

3. Build the Worker and deploy it:

    ```sh
    pnpm build --filter=@turborepo-remote-cache/server
    pnpm run deploy
    ```

    Wrangler creates the `turborepo-cache` R2 bucket on the first deploy and prints the Worker's URL, such as `https://turborepo-remote-cache.<your-subdomain>.workers.dev`.

4. Set the token:

    ```sh
    pnpm --filter @turborepo-remote-cache/server exec wrangler secret put TURBO_TOKEN
    ```

    Wrangler asks for the value. Paste your token.

:::tip
To create the bucket in a specific location, create it before the first deploy: `pnpm --filter @turborepo-remote-cache/server exec wrangler r2 bucket create turborepo-cache --location weur`. [R2 storage](/storage/r2) lists the options.
:::

## Check the deployment

Replace the URL with your Worker's URL. `/ping` needs no token:

```sh
curl https://turborepo-remote-cache.<your-subdomain>.workers.dev/ping
```

The Worker answers `pong`. Now check the token:

```sh
curl -H "Authorization: Bearer <your token>" \
  https://turborepo-remote-cache.<your-subdomain>.workers.dev/v8/artifacts/status
```

The Worker answers `{"status":"enabled"}`. A `401` response means the token doesn't match `TURBO_TOKEN`.

## Point turbo at the cache

Set these variables where `turbo` runs, with your Worker's URL and no trailing slash:

```sh
export TURBO_API=https://turborepo-remote-cache.<your-subdomain>.workers.dev
export TURBO_TOKEN=<your token>
export TURBO_TEAM=my-team
```

Then run a task twice, such as `turbo run build`. [Connect turbo](/connect-turbo) explains each variable, the alternatives to environment variables, CI setup, and how to check that a hit came from the remote cache.

## Deploy from GitHub Actions

The repository's [deploy workflow](https://github.com/AdiRishi/turborepo-remote-cache-cloudflare/blob/master/.github/workflows/deploy.yml) builds and deploys the Worker on every push to `master`. To run it in your copy, add these repository secrets:

- `CLOUDFLARE_API_TOKEN`: a Cloudflare API token that can edit Workers and R2.
- `CLOUDFLARE_ACCOUNT_ID`: your Cloudflare account ID.
- `TURBO_TOKEN`: the token for the Worker. The workflow sets it as the Worker's secret on every deploy.

:::warning
If the `TURBO_TOKEN` secret is missing, the workflow sets the Worker's token to `SECRET`. Add the secret before the workflow first runs.
:::
